# 性能验证

日期：2026-10-15。macOS / Apple Silicon，以下历史对照使用本机优化编译 `swiftc -O -swift-version 5`；当前基准已迁移到 SwiftPM release 测试目标。

## 对照结果

基线是初始 Git 提交 `74dd40e`，通过 `git archive` 取出独立源码，再运行与优化版本完全相同的基准。每个版本各构建一个临时测试程序。数据均位于临时目录：100 个合成会话目录、10,000 个图片文件（5,000 组）和 1,000 个普通文档，无通知记录。

| 测量项 | 基线 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 首次索引 | 3390.37 ms | 2228.61 ms | 耗时减少约 34% |
| 无变化重扫（3 次中位数） | 3239.18 ms | 1241.27 ms | 耗时减少约 62% |
| 每次无变化重扫的 SQLite 行写入 | 11,004 | 4 | 不再改写未变化的文件记录 |
| 图片分页及总数查询（20 次中位数） | 13.21 ms | 6.91 ms | 耗时减少约 48% |

行写入通过同一连接的 `total_changes()` 差值测量，两边各 3 次结果相同。优化后的 4 行是两种目录扫描的根目录及扫描状态元数据。

本基准测量目录遍历、格式探测、数据库写入和图片分组查询。图片文件是仅有格式头的合成 DAT，不进行解密、解码或预览生成；分页测试没有预览 payload。首次索引指新建档案的首轮扫描，文件系统缓存没有清空，不代表磁盘冷缓存。结果不是实际微信图片解码速度、界面帧率、CPU 占用或内存峰值，实际耗时随文件量和设备变化。

## 优化内容

- 目录扫描按 ID 比较文件大小、修改时间和可用性，只更新新增、变更或重新出现的文件；完整扫描才标记缺失文件，不完整扫描保留未访问记录。
- 图片大小和修改时间相同时复用此前读到的格式；此前不可读的文件头仍会重试。文件访问和后续预览仍保留路径检查。
- 目录图片先分页选择 60 组，再批量读取版本和预览；每组仍最多 100 个版本。增加分组及最近图片索引，支持旧档案缺少预览表的情况。
- 日期格式器按线程复用；哈希使用直接十六进制编码，保留已有消息及文件 ID。
- 图片预览显示在独立后台队列读取、解压；内存缓存设置 32 MB 成本预算和 128 项上限，缓存命中时仍检查文件。视图任务取消后不应用过期结果。
- 批量生成预览时逐图释放自动释放池，仅在实际遇到待解码的 V2 DAT 时探测本地密钥候选。
- 图片和普通文件搜索合并 250 ms 内的连续输入，过期查询结果不会覆盖当前搜索。
